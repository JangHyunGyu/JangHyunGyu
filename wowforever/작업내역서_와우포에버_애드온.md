## 4. DruidMacros (직접 만든 애드온)

### 4-1. 기능 요약
- 로그인할 때 드루이드 한글 매크로(DM1~DM=, DMQ/DME/DMR/DMF, DM 숨기, DM 섬광곰, DM 위상, DM 돌진발톱, DM 표범마무리, DM 변신해제)를 만들거나 고칩니다.
- 폼별 단축바(사람 1~12, 표범 73~84, 숨기 85~96, 곰 97~108, 달빛야수 109~120)에 자동으로 배치합니다.
- 폼 번호는 실행할 때 감지합니다. 바다표범을 안 배웠으면 표범이 2번입니다. 아직 안 배운 주문은 배우면 자동으로 켜집니다.
- 명령어
  - `/dmacro 배치`(setup): 추천 배치로 다시 놓기
  - `/dmacro 복구`(restore): 처음 설치하기 전 배치로 되돌리기
  - `/약초` 또는 `/herb`: 약초지도 표시 켜기/끄기 (Shift+M이나 Alt+M 중 빈 키에 자동 연결)
- 그 밖의 기능
  - GatherMate2_Data 약초·광맥 데이터를 자동으로 가져옵니다.
  - 자동 루팅을 한 번 켭니다(`autoLootDefault=1`).
  - `ActionButtonUseKeyHeldSpell=1`로 1~5번 꾹 누르기 연타가 됩니다.
- SavedVariablesPerCharacter: `DruidMacrosDB` (`bindv`=5, `extrav`=2, `autoloot` 등)

### 4-6. Q/E 버그의 원인과 5.4 해결 방식 (다음 사람이 꼭 알아야 할 것)
- **증상**: 표범에서 Q(또는 곰에서 E)를 다시 누르면 몸은 표범/곰인데 단축바에 사람 스킬이 나옴.
- **원인 (게임에서 확인)**
  - 한 번 누를 때 폼 해제와 재변신(`/cancelform` + `/cast !Cat Form`)이 같이 일어나면, 포에버 클라이언트는 GetShapeshiftForm()=3인데 **GetBonusBarOffset()=0**, HasBonusActionBar=false인 상태로 계속 남습니다.
  - 이벤트 순서는 SHAPE f0 → BONUS f0 b0(블리자드가 actionpage를 1로 바꿈) → SHAPE f0이고, 폼이 돌아온 뒤에는 이벤트가 하나도 오지 않습니다.
  - 블리자드 ActionBarController는 UPDATE_BONUS_ACTIONBAR, VEHICLE, OVERRIDE, ACTIONBAR_PAGE_CHANGED 이벤트에서만 페이지를 바꿉니다. 변신 이벤트로는 바꾸지 않습니다.
- **5.4 해결**
  - 보안 헤더 프레임 `DruidMacrosBarFix`(SecureHandlerStateTemplate)를 둡니다. 상태 드라이버는 `"[bonusbar]b;[form:FC,stealth]s;[form:FC]c;[form:FB]r;n"`입니다(FC/FB는 실제 표범/곰 폼 번호).
  - `b`(보너스 바 정상): 아무것도 안 합니다.
  - `s`/`c`/`r`(폼은 있는데 보너스 바가 없음): MainActionBar의 actionpage를 숨기 8, 표범 7, 곰 9로 바꾸고 `dmon` 표시를 남깁니다. ActionButton1~12에 아무 속성(`dmfix`)이나 설정해서 OnAttributeChanged → UpdateAction으로 다시 그리게 합니다.
  - `n`(사람): 직접 바꾼 페이지가 있을 때만 `GetActionBarPage()`(1~6, 범위 밖이면 1)로 되돌립니다.
  - 전투 중이 아닐 때 Run()의 MakeMacros() 직후 `FixBar()`로 등록합니다.
- **교훈**
  - **상태 드라이버 상태 이름에 숫자를 쓰면 안 됩니다.** 보안 환경에서 숫자처럼 보이는 값은 숫자로 넘어와서 `newstate=="0"` 비교가 실패하고, 페이지 0(액션 -11)이 되면서 오류가 납니다. 반드시 글자(b/s/c/r/n)를 쓰세요.
  - MainActionBar의 actionpage에 상태 드라이버를 직접 걸면 안 됩니다(5.2 실패).
  - 보안 스니펫 안에서도 `GetActionBarPage()`와 `[bonusbar]` 조건은 동작합니다.
  - 폼 번호: 1 곰(5487/9634), 2 바다표범(1066), 3 표범(768). 보너스 페이지: 표범 7(칸 73), 은신 8, 곰 9(칸 97).
- **5.4 검증 결과** (`/reload` 후 실제 키 입력으로 시험. 값은 폼, 보너스, 페이지, 버튼1 액션, 상태 순)
  - Q1 `3 1 7 73 c`, Q2 `3 1 7 73 c`, Q3 `3 0 7 73 c`(버그 상태를 표범 페이지로 보정), F1 `0 0 1 1 n`, E1 `1 3 9 97 r`, E2 `0 0 1 1 n`, E3 `1 3 9 97 r`, F1b `0 0 1 1 n`
  - 새 Lua 오류는 없었습니다.
  - E2처럼 매크로가 가끔 폼만 풀고 다시 변신하지 못하고 사람으로 끝나는 경우가 있습니다(기존 매크로 동작). 이때 사람 바가 나오는 것은 정상입니다.
  - **전투 중 Q/E 확인은 아직 못 했습니다.**
